# Automation agent operating instructions

## Objective

Execute the repository's real-data Windows workflow and leave only evidence that was produced by the declared pipeline.

Canonical command from PowerShell or a Windows-capable automation shell:

```powershell
.\scripts\showcase.cmd
```

If an agent invokes Python directly, it must use the Windows environment resolved by `scripts/windows_common.ps1` (normally `%USERPROFILE%\.gvo\venv-py314\Scripts\python.exe`) and preserve the workflow ordering implemented by `scripts/run_showcase_pipeline.py`.

## Non-negotiable scientific rules

- Never invent, copy, hand-edit or estimate model metrics.
- Never use synthetic fixtures as README/publication evidence; synthetic data is test-only.
- Never use external-test AOIs for seed, architecture, threshold or hyperparameter selection.
- Never move AOIs between train/validation/external splits to improve scores.
- Never weaken a release threshold during a run merely to make a result pass.
- Keep WorldCover described as a model-derived reference map, not perfect pixel ground truth.
- Keep Hansen forest-loss data contextual rather than claiming it is temporally aligned land-cover truth.
- Do not claim operational environmental, regulatory, cadastral, emergency, household or person-level accuracy.

## Security and integrity rules

- Do not add user-controlled arbitrary outbound URLs.
- Preserve HTTPS-only source access, exact host allowlisting, redirect rejection, bounded downloads, budgets, retries and circuit breaking.
- Never deserialize untrusted pickle/checkpoint objects in serving code; deployment uses verified `torch.export` PT2 bundles.
- Do not bypass SHA-256 verification for model or evidence files.
- Do not commit secrets, `.env`, curated raster datasets, databases, caches or temporary training state.
- Preserve least-privilege container settings in the optional Docker Desktop deployment.

## Engineering rules

The flagship is one completed six-band Sentinel-2 land-cover segmentation model. Do not add unvalidated model families for appearance. Prefer bounded resource use, deterministic behavior, resumability, clear failures, provenance and testable code.

Windows is the primary host contract. Do not replace PowerShell/.cmd entry points with WSL/Bash requirements.

## Publication acceptance criteria

A measured release is publishable only when:

1. Real Sentinel-2 and WorldCover data were curated for every frozen AOI.
2. Curated output hashes verify before reuse.
3. Seed selection used validation AOIs only and records that the external test was not used.
4. The final model was deterministically retrained with the selected seed.
5. Stockholm/Tallinn external evaluation happened only after selection was frozen.
6. `models/landcover/bundle.json` verifies every support file by SHA-256 and size.
7. Evaluation, seed-selection, showcase-summary and release-gate evidence are mutually consistent.
8. README results were generated by `scripts/build_showcase.py`, not manually authored.
9. The research showcase gate is recorded exactly from measured evidence; a threshold miss remains non-eligible but does not block local runtime.
10. Publication/CI work uses strict quality mode: Ruff, strict mypy, tests, >=80% branch coverage, package build and dependency audit must pass.
11. CI validates the primary repository on Windows; optional container security checks remain green.
12. No caches, databases, raw datasets, credentials or stale generated evidence are published.

If networking prevents real data acquisition, report the blocker and keep the repository explicitly untrained. Never create substitute showcase evidence.
